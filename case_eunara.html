Case Study 03 · Personal Project · macOS AI Assistant

은아라

A calm, bilingual AI assistant that lives quietly on the desktop — closer to Siri or Copilot than to a character widget. She has a face (a pixel-art design of my own), but the point of the project is the chat and task system underneath it: reactive, never gamified, there to help a scattered thought become an actionable one.

Role Character Designer · Developer Stack Electron · SQLite · OpenRouter
恩

01 — What She's For

An Assistant First, a Character Second

Not a productivity tool wearing a mascot costume, and not a chat character built around a face — an AI assistant that only speaks when spoken to, and helps turn a messy situation into one clear next step. The character is how she's represented on screen, not the reason she exists.

The Challenge

Design a desktop assistant who feels calm and present rather than like another notification — and validate the one technical assumption everything else depends on: an always-on-top window that actually holds over fullscreen macOS apps.

The Goal

A light chat and task system that helps externalize thinking — fluently, in both Korean and English — paired with a face that never gamifies engagement.

02 — The Face of the Assistant

Designed to Recede, Not Perform

Hand-drawn, then adapted into pixel art. A few silhouette-breaking details — the off-shoulder jacket, the long ribbon streamers — each has to earn its place at sprite scale, since the face is meant to sit quietly on screen rather than draw attention to itself.

03 — How She Runs

Reactive by Design

Strictly reactive — the Dock icon is her only show/hide control, and she has no engagement mechanics to speak of. This is the part of the project that actually makes her an assistant rather than a desktop pet.

01

Reactive Core

No notifications, no nudges. She answers when the conversation opens and holds still otherwise.

02

Bilingual by Default

Korean-English text chat, plus on-device Korean wake word detection via Porcupine.

03

Session Memory

Chat resumes from SQLite history, with a per-session "where I left off" summary and thread compaction for long runs.

04 — Scope & Risks

What's Decided, What's Deferred

The single most critical unvalidated assumption gets tested before anything else is built further. Everything here is scoped on purpose, not by accident.

Risk

Always-on-top over fullscreen macOS apps is unvalidated — if it fails, the architecture needs a real rethink.

In

Scoped in: reactive chat, task/situation organization, session memory, bilingual support, model switching with per-message cost logging.

Out

Scoped out, for now: Claude Design, Cowork, and Code integrations, cut after early scope creep. Voice input is a possible future, not a current one.

Handoff

Copy-context-to-clipboard for Claude Desktop — manual, deliberately, over a more complex direct integration.

05 — Where It Stands

Architecture Settled, Sprite Sheet Next

Architecture is settled on paper. The always-on-top test comes before the sprite sheet is finalized.
