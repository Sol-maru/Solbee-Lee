Portfolio Website · UX/UI Design

Woobee Archive

My personal portfolio site, built from scratch with HTML, CSS, and JavaScript — and, as of September 2026, rebuilt from an archival forest-green/parchment identity into a porcelain-and-evergreen system that reads as quiet, professional, and a little bit dark academia.

Role Designer · Developer Stack HTML · CSS · JavaScript Hosted on GitHub Pages Status In Progress

01 — Overview

What is Woobee Archive?

Woobee Archive is my personal portfolio website — a space to archive and present my work across fine arts, graphic design, and UX/UI. The name plays on my nickname "Bee" and the idea of an archive: a living collection that grows over time.

The site is built entirely by hand with HTML, CSS, and vanilla JavaScript — no frameworks, no templates — and hosted on GitHub Pages. In September 2026 I moved the whole thing off its original identity (deep forest green, parchment, brass accents, dashed "aged document" borders, a floating pill nav) onto a new system built around two colors: porcelain and evergreen.

The Challenge

The old archival theme fought against what it was supposed to hold — UX/UI case studies, fine art paintings, and a pixel-art character design all sitting under the same skeuomorphic folder icons and brass borders. It read as antique rather than intentional.

The Goal

A professional, green-based system — conceptual and utilitarian, with just enough dark-academia gravitas — where serif type is used sparingly, only as a highlight for my name and project titles, and everything else is carried by a plain mono/sans type system.

02 — Design Decisions

Porcelain, Evergreen, Moss

The new palette is two anchors — porcelain (#FBFEF9) as the paper/surface and evergreen (#19381F) as the near-black ground — with moss (#5E7A63) as the supporting mid-tone that ties them together. Serif type (AW Conqueror Stincilla, falling back to Stardos Stencil, then Noto Serif KR for Hangul glyphs like 은아라) is reserved strictly for highlight moments — my name and project titles. Everything else runs on Inter for body copy and IBM Plex Mono for labels, tags, and index numbers.

01

A no-box navigation

The primary nav is fixed top-right with mix-blend-mode: difference, so one plain-text nav auto-inverts and stays legible over both the dark hero and the porcelain content below — no boxes, no pills, no borders.

02

Shared CSS architecture

One main.css file holds the design tokens and every page's styles, scoped by a body class per page (page-home, page-about, page-archive, page-woobee) so each page can be migrated onto the new theme independently.

03

Hairlines, not borders

Dashed brass borders and card shadows were replaced with single 1px hairlines (--hairline-on-light / --hairline-on-dark) — a quieter, more drafting-table way to separate content.

03 — The Hero

A Pinned Hero, Rebuilt Three Times

The homepage hero is full-viewport and stays pinned in place while the project list scrolls up to cover it — done in pure CSS (a position: fixed hero, a same-height spacer, and a normal-flow section with a higher z-index and an opaque background), no scroll-driven JavaScript required.

The interactive light inside that hero went through three iterations based on feedback: a cursor-tracking spotlight first, then pond-style ripples that expanded and faded from the pointer, and finally a metaball blob field — several translucent moss-colored circles merged with an SVG goo filter (blur + contrast), styled deliberately translucent rather than solid so the name and intro text underneath stay legible, plus a couple of static thin-line circles for an astronomical-diagram kind of texture.

v1

Cursor spotlight

A radial-gradient light following the pointer — the first pass, functional but static.

v2

Pond ripples

Rings spawned and expanded from the pointer on movement, like water — closer to "interactive," but not the mood.

v3

Metaball blobs

Translucent green-grey blobs that drift and merge, one trailing the cursor — the current version.

04 — Project Index

List on the Left, Preview on the Right

Below the hero, the homepage lists four UX/UI case studies (Project ND, Archive, 은아라, MuzTime) with the mini tag now shown directly under each title, not just on hover. Hovering or focusing a row pops up a preview panel on the right with that project's tag, title, and description — completely hidden by default (no idle state, no empty-panel placeholder), scaled and sized to actually use the space the narrower list column leaves open.

Key details

  • CSS-only pinned hero (fixed + spacer + overlay)
  • SVG goo filter for the metaball light
  • Popup preview panel, opacity/pointer-events toggled by JS
  • Custom ease-out scroll animation (no native easing control)
  • Scoped per-page theming via body classes in one shared CSS file
  • Hosted on GitHub Pages

06 — Reflection

What I'm Learning

Rebuilding a site's whole identity mid-flight is different from starting one from scratch — every new page has to slot into decisions (palette, type, nav) made earlier, and every old page left un-migrated is a visible reminder of how much is left.

What went well

The two-color spine (porcelain/evergreen) made every later decision easier — I could ask "does this read as archival or as the new system?" and usually know the answer immediately. The CSS-only pinned hero held up well across three completely different light effects without needing to be rebuilt.

What's next

Extending the same theme to Contact and Shop, and to the individual project case studies (Project ND, MuzTime, 은아라). Replacing the placeholder gradients above and in the project preview panel with real screenshots. Deciding where Contact belongs now that it's off the primary nav.
